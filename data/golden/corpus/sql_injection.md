# SQL injection 与参数绑定

## Parameterized values

SQL 注入发生在不可信输入被拼接成查询语法时，攻击者可能改变原本的条件或执行范围。参数化查询把值与 SQL 结构分离，驱动负责绑定参数，避免把字符串内容解释为语法。不要用手工转义或过滤几个关键词替代参数绑定；数值、日期与批量条件也应使用数据库驱动支持的安全参数接口。

## Dynamic identifiers

表名、列名与排序方向通常不能作为普通值参数绑定。动态查询需要把用户选择映射到服务端固定的允许列表，再组合受控语法片段。直接把 sort 参数放进 ORDER BY，即使 WHERE 中的值已绑定，仍可能留下结构注入入口；权限检查和查询复杂度限制也要保留，参数化本身不会阻止所有资源滥用。

## Layered protections

数据库账号应只具有应用必需的操作权限，错误响应避免向用户暴露完整 SQL 与内部结构。安全测试需要覆盖编码差异、异常参数和多入口查询，不能只试一个常见攻击字符串。慢查询限制与审计可以降低影响并辅助调查，但无法替代安全构造查询；日志也应避免直接记录含敏感值的完整语句。
