# Hash index 与哈希碰撞

## Equality lookup

Hash index 将键映射到哈希桶，主要用于支持等值条件。键的哈希值不保留原始大小关系，因此不能依靠桶顺序直接完成价格区间扫描或有序输出。是否优于 B-tree 需要结合数据库实现、数据规模与缓存命中率判断；不能仅凭平均查找复杂度就认定任何等值查询都应改用哈希索引。

## Collisions

不同键可能拥有相同哈希值，这称为哈希碰撞。索引必须保留足够信息继续核对原始键，不能把哈希值相等当成业务标识相等。桶过满会增加候选比较与溢出访问成本，因此需要观察键分布和装载情况；哈希函数输出位数有限，也不可能对无限输入提供绝对无碰撞保证。

## Distinct meanings

哈希索引、内容摘要与密码哈希服务于不同目标。数据库哈希索引关注查找位置，内容摘要关注字节内容的一致性，密码存储则需要盐和专用慢哈希算法。用一个快速通用哈希替代密码哈希会降低离线猜测成本；选择算法时必须明确威胁模型，不能因为名称都有 hash 就互换实现。
